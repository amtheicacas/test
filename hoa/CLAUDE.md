# CLAUDE.md: Heron Landing HOA Violation Manager

Django 5.2 app (folder `hoa/`) for Heron Landing HOA (Sarasota FL): violation notices, owner portal, Board queue, Compliance Committee hearings/minutes, fines, certified mail, Zoom. **Read `PROJECT_STATUS.md` first** (architecture, schema, decisions, open items, where we left off). `README.md` has feature docs (some sections predate later changes; see PROJECT_STATUS.md "Doc drift"). `STATUSES.md` is the regenerated status/label table; `TESTING.md` is the manual test checklist.

## Run / test (Linux sandbox)
- venv: `/tmp/claude-0/venv/bin/python` (recreate if gone: `pip install -r requirements.txt pytest pytest-django`)
- Tests: `/tmp/claude-0/venv/bin/python -m pytest -q` (~60 s, 943 tests + 1 skipped on SQLite [944 on PostgreSQL], must all pass before every commit; they run on `config.test_settings`, i.e. as a development site). Checks: `manage.py check`, `manage.py makemigrations --check --dry-run`.
- Local: `start-site.bat` (Windows, user's PC; runs `migrate`, sets `DJANGO_DEBUG=1` and `MFA_REQUIRED_ROLES=none`). **A site is LIVE unless `DJANGO_DEBUG=1`**: a live site refuses to start without real SECRET_KEY / ALLOWED_HOSTS / SITE_URL (https) / DATABASE_URL / EMAIL_HOST / DEFAULT_FROM_EMAIL and with two-step login on (`config/deploy.py`). On the user's PC, commands run in a terminal need `DJANGO_DEBUG=1` in `local.env`. Live installs use `requirements-production.txt`. Secrets go in untracked `hoa/local.env` (see `local.env.example`).
- Git: develop on branch `claude/brave-galileo-mddme9`, commit + `git push -q origin <branch>`; end commit messages with the Co-Authored-By / Claude-Session trailers from the system reminder. Never create a PR unless asked. **Chain commands with `&&`, not `;`, so a failing test never gets pushed.**

## Architecture (all in `violations/`)
`models.py` data; `services.py` ALL workflow transitions and rules (raise `WorkflowError`; views stay thin); `views.py`+`urls.py`; `progress.py` owner/staff trackers + sentences; `pdf.py` letters (reportlab); `minutes.py` committee minutes; `portal.py` owner tile registry; `accounts.py` roles/logins/magic links; `mailing.py` Lob; `zoom.py`; `vantaca.py` import/sync; `ledger.py`; `geocoding.py`; `standards_search.py`. ## Rules to keep
- **Roles:** manager and board are IDENTICAL (same access, incl. admin). `committee` = roster-driven. `homeowner` = owner login. One person can be owner + committee/board on ONE login (`Profile.owner` set; `accounts.owner_of`); owner pages must check `owns(user, v)`, never `can_view`.
- **Owners never edit their own info** (name/email/address come from Vantaca; read-only portal). Letters never show the management company (HOA letterhead, "On Behalf of the Board of Directors").
- **Windows:** the user runs this on Windows. Never use `strftime("%-d")`; use `short_date()` / `f"{d:%b} {d.day}"`. Keep paths/encodings portable.
- **Never send anything automatically to outside parties that wasn't asked for:** attorney email is a reviewed draft; owner emails/letters follow the workflow only.
- Fines: Declaration 8.1 and FS 720.305: $100/violation, continuing violation $100/day up to $1,000; suspension max 60 days (not offered; no amenities); fine due 30 days after delivery (+5 mail buffer); hearing needs 14 days' notice (warn under 20).
- Change behavior in `services.py`, add/adjust tests, regenerate `STATUSES.md` with `manage.py print_statuses` if statuses/labels change. All user-visible wording belongs in one place (`progress.py`, `Violation.PORTAL_LABELS`, status choices).
- New model fields need a migration (`makemigrations`); data fixes go in migrations with `RunPython`.
- Integrations (Lob, Zoom, Vantaca API/ledger, Census geocoder) are written to documented shapes but **never run live**: say so when touching them.
- Don't modify docs by deleting; append or mark superseded.

## Saved letters, case file, suspension (Part A, done)
Every letter emailed or handed to Lob is saved as the EXACT PDF (`SentLetter`, add-only: no edit/delete in code, admin read-only; `letters.py`; hooks in `services.send_notice` / `mailing.dispatch` via `services._keep_copy`; SHA-256 fingerprint, deduped by hash). The hearing notice attaches the saved ORIGINAL Notice of Violation only (`letters.original_notice_copy`, pypdf merge in `pdf.render_notice_pdf`); with no saved original it falls back to the old rebuilt copy and logs a NOTE. Case page: "Exact copies of letters sent" card + "Download the case file (zip)" (`casefile.py`, staff only, each download logged as an Event). Files live in default storage (MEDIA_ROOT locally; private S3-compatible bucket when STORAGE_BUCKET is set; a live site must set one or MEDIA_ROOT). Suspension is hidden everywhere in screens/workflow unless `SUSPENSION_ENABLED=1` (tests run with it ON via `config/test_settings.py`; `test_suspension_hidden.py` covers OFF). **The letters' wording and layout are frozen until the attorney's final Word files arrive (Part B); do not edit them.** New dependency `pypdf` (start-site.bat now runs `pip install -r requirements.txt`).

## Site-visit observations (internal, add-only)
Committee members, Board and manager add notes and photos per case (committee meeting page, per case card; also the staff case page) from a drive-through. **Owners must never see any of it**: not on any owner page, owner PDF, JSON or the minutes; never add it to those. `sitevisits.py` (`blocked_reason`: role must be committee/board/manager, case issued, NOT the owner's own household [owner login OR roster `owner` OR conflicted member], committee only for cases they can see), models `SiteVisitObservation` / `SiteVisitPhoto` (original bytes + SHA-256) / `SiteVisitAccess` (audit), all `_AddOnly` (save/delete refuse; admin look-only). Corrections = a new observation with `corrects`. They are NOT committee findings and never change the case (`committee_findings` is untouched). Views `site_visit_add`, `site_visit_photo` (fingerprint re-checked, never cached). Files in default storage under `site-visits/` (same private storage as photos and saved letters). The case-file zip gets a `Site-Visit-Observations/` folder + a top-level `manifest.csv`; it is left out when the downloader owns the violation. Access log: views and photo opens are de-duplicated per person for 10 minutes. Test settings use a fast password hasher (tests only).

## Uploaded minutes (SEC-15, done)
`minutesfiles.py` + add-only `MinutesFile` (migration 0042). Only PDF and Word `.docx`, judged by CONTENT (pypdf parse; zip structure; refuses macros, embedded objects, PDFs with /JavaScript or /Launch, zip bombs); old `.doc`, text and pictures are refused. Stored under a random name (`minutes/<year>/<token>.<ext>`), uploader's file name kept as display text only. Uploading again adds a new row (`replaces` = previous) and never deletes the old file; the meeting page lists the history. Download = `meeting_minutes` view only (committee/Board/manager), always as an attachment with a fixed type, no-store, fingerprint re-checked (409 on mismatch). `CommitteeMeeting.minutes` (old FileField) is no longer written; files uploaded before this are still offered, as a download only. Retention default is now 7 years (`ARCHIVE_RETENTION_YEARS`).

## File backup (copy only)
`backups.py` + `manage.py backup_files` (`backup-files.bat` on the PC): copies every file in the live storage (Backblaze B2) to the backup bucket (Cloudflare R2) using the `BACKUP_*` settings (its own key; the website never has it). COPY ONLY: no code path deletes or overwrites in the backup (a same-name different-size file is a CONFLICT and left alone); every new copy is read back and fingerprint-checked; then it checks that every file name the database refers to (any FileField of any model) is in the backup; exits with an error if anything is wrong; optional `BACKUP_HEARTBEAT_URL` is pinged only after full success; `--dry-run`, `--verify`. `storage-check/` test files are skipped. 
`manage.py backup_database` (`dbbackup.py`): dumps the database (PostgreSQL: `pg_dump --format=custom`; SQLite on a PC: `connection.connection.serialize()`; do NOT use sqlite3 `backup()` in tests, it hangs on a busy in-memory DB), encrypts with the age PUBLIC key `BACKUP_PUBLIC_KEY` (pyrage, standard age format: the `age` tool opens it too), stores `database/hoa-<date-time>.<dump|sqlite3>.age` in the backup bucket, refuses to overwrite, reads back and compares SHA-256, pings `BACKUP_DB_HEARTBEAT_URL` only on success. `make_backup_key` creates the key pair ON THE USER'S PC (private key to a file, never printed; gitignored `backup-private-key*`); `decrypt_backup <file.age> <key file> <out>` for restores. The server never holds the private key. Key custody: the user plus one other person.

## Accounts, audit log, admin limits (Phase 4)
- `AuditLog` (add-only, migration 0043; `audit.record(action, subject, detail, actor=, request=)`, `audit.diff`): logins, roles, sign-in emails, owner changes made by the Vantaca sync, roster, meetings (create/reschedule/cancel in `services`), standard responses, minutes uploads, owner (re)activation, syncs/imports, admin edits. Actor name is stored as text. NEVER put a password, token or key in `detail`. Pages (Board/manager only): `/audit/`, `/staff-logins/`, `/owners/<id>/logins/`.
- `accounts.change_signin_email(profile, new, actor, reason, request)`: the ONLY controlled way to change who can sign in to a household (updates login + the owner record's matching address, cancels unused links, ends sessions, audits, emails the OLD address a notice [full new address never shown] and sends the first link to the NEW one). Refuses duplicates and addresses on another household. Vantaca remains the source of truth: the next sync restores Vantaca's address unless Vantaca is updated too (the page says so). The Vantaca-driven swap in `sync_account` now also cancels links, ends sessions, audits and notifies.
- `accounts.reset_two_step(user, actor, reason)`: lost phone. A DIFFERENT Board member/manager, reason required; removes the authenticator, ends sessions, emails the person, audits. `accounts.end_sessions(user)`: sign out everywhere.
- Admin (`SafeAdmin` in `admin.py`): deleting Owner/Violation/CommitteeMeeting/CommitteeMember/CannedReply/ViolationType/User is allowed only when `DEBUG` (development); owner email fields are read-only once the owner exists; TOTP devices are look-only with the secret `key` excluded; every admin change is audited (old -> new, passwords only as "password changed"); the admin address is `settings.ADMIN_URL` (default `admin/`; set a hard-to-guess one live).
- `middleware.NoStorePrivatePages`: signed-in responses get `Cache-Control: no-store, private` unless the view set its own header (file downloads do).

## Certified + first-class mailing by hand, tracking, "not delivered" alert (PROJECT_STATUS.md section 32)
`MailPiece` = one physical letter; `by_hand` pieces are created by `mailing.plan_manual_pieces` for hearing notices and decision letters when `MAIL_PROVIDER` is not `lob`. Record changes ONLY through `services.record_piece_mailed/delivered/not_delivered/handled` (they keep `Notice.mailed_on/method/tracking_number/return_receipt_on` in step via `_sync_notice_from_pieces`, and write the case history). A certified letter needs a tracking number to be marked mailed. The red "Certified mail problems" box (first thing on the staff dashboard) and the menu "N to do" count use `needs_attention`, `to_mail` and `services.certified_to_check()`. Staff-only notes (`problem_note`, `handled_note`) and "to be mailed" items must never reach an owner page (owners get `correspondence(v)` which shows only `is_mailed` letters). Letter wording/layout untouched; the printed letter shows only the first certified number (known limit, waits for Part B). Route `mail_piece_action` is STAFF_ONLY in `test_access_matrix.py`.

## Mail goes through Lob, never by hand (PROJECT_STATUS.md section 33)
The Association will NOT mail by hand: all first-class and certified mail goes through Lob. `MAIL_PROVIDER=manual` and its `by_hand` pieces are only a fallback. `mailing.lob_send` must keep sending `use_type=operational` (Lob refuses a request without it), cuts names to 40 characters, and raises Lob's own error message; `PROBLEM_WORDS` follow Lob's certified event names. Lob test keys do not mail and have no certified tracking events, so the returned-mail flow is unproven until real certified letters are sent (needs the owner's explicit approval: "do not mail or send anything real"). The envelope RETURN ADDRESS (`HOA_RETURN_*`) is undecided and must not show the management company.

## Lob safety checks (PROJECT_STATUS.md section 33 update)
`mailing.lob_send` refuses to send (before any network call) with no key, or with anything but a `test_` key unless `settings.PRODUCTION and not settings.STAGING`: test copies and staging can never mail for real, and the live site's start check (`deploy.production_problems`) refuses a test key. Keep that. `manage.py check_lob [--ping]` sends nothing (ping = a free read-only call); never print the key (length only). Return name = `mailing.return_name()` (`HOA_RETURN_NAME`). Tests set `settings.PRODUCTION`/`STAGING` explicitly when they need a live-site case.
